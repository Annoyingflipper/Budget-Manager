# v2.1 — Mesada: Install + Identity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the app installable from Chrome on macOS as "Mesada", with a real icon and wordmark, and cut the single 493 kB bundle down by code-splitting the routes.

**Architecture:** A `public/` directory (new to this repo) holds a hand-drawn flat SVG mark, a web app manifest, and PNG icons rendered from that SVG by a Playwright-driven script. In-app, one `Wordmark` component replaces three copy-pasted `💵` + "Budget" blocks. `ThemeProvider` syncs the `theme-color` meta so the standalone window's title bar tracks the active theme. `App.tsx`'s three secondary pages move behind `React.lazy`, and a post-build script pins the result so it can't regress.

**Tech Stack:** React 19, Vite 8, TypeScript 6, Tailwind 4 (CSS-first, no `tailwind.config.js`), Vitest 4 + React Testing Library 16, Playwright 1.60.

**Spec:** [`docs/superpowers/specs/2026-09-20-mesada-pwa-branding-design.md`](../specs/2026-09-20-mesada-pwa-branding-design.md)

## Global Constraints

- **Test-first, no exceptions.** Write the test, run it, confirm it fails *for the intended reason*, then implement. A test that has never been observed failing is not evidence. This applies to rewritten tests too.
- **Branch:** all work lands on `staging`. Never push to `main` — that triggers the PRD deploy and requires the user's explicit authorization.
- **Never create pull requests.** Solo workflow: direct push to `staging`.
- **No new runtime dependencies.** Nothing may be added to `dependencies` in `package.json`. `devDependencies` may only grow if a task says so explicitly (no task in this plan does).
- **No schema, RLS, auth, or migration changes.** This release is entirely client-side.
- **Do not change `VITE_APP_URL`**, the Vercel project names, the Supabase project refs, or the GitHub repo name. Changing `VITE_APP_URL` desynchronises the user's existing TOTP factor.
- **App name is exactly `Mesada`** — capital M, no tagline, no "Budget Manager" anywhere user-visible.
- **Icon coin faces must stay blank.** No `$`, no currency glyph of any kind. The app handles USD, EUR and VES.
- **`npm test` is `vitest run --mode development`.** Plain `vitest run` fails: without development mode, `.env.development.local` is not loaded and `src/lib/supabase.ts` throws at import. Always use `npm test`.
- **Commit message trailer:** every commit ends with `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.

### Task 1: Theme background colour map

The `theme-color` meta needs a background value per theme × mode. Reading it from computed CSS is untestable — jsdom does not load `src/index.css`, so `getPropertyValue('--bg')` returns `''`. So the values live in TypeScript, and a test parses `src/themes.css` to prove the two never drift.

**Files:**
- Create: `src/theme/themeColors.ts`
- Test: `src/theme/themeColors.test.ts`

**Interfaces:**
- Consumes: `Theme`, `Mode` from `src/theme/types.ts`.
- Produces: `THEME_BG: Record<Theme, Record<Mode, string>>` and `backgroundFor(theme: Theme, mode: Mode): string`. Task 2 uses `backgroundFor`.

- [ ] **Step 1: Write the failing test**

Create `src/theme/themeColors.test.ts`:

```ts
import { describe, it, expect } from 'vitest';
import { readFileSync } from 'node:fs';
import { resolve } from 'node:path';
import { THEME_BG, backgroundFor } from './themeColors';
import type { Mode, Theme } from './types';

const THEMES: Theme[] = ['peach', 'sage', 'lavender'];
const MODES: Mode[] = ['light', 'dark'];

/**
 * Pulls the --bg declaration out of each `:root[data-theme=X][data-mode=Y]`
 * block in themes.css. The peach/light block is written as a grouped selector
 * (`:root, :root[data-theme="peach"][data-mode="light"]`), so the theme/mode
 * pair is matched anywhere inside the selector list rather than anchored.
 */
function bgFromCss(theme: Theme, mode: Mode): string {
  const css = readFileSync(resolve(__dirname, '../themes.css'), 'utf8');
  const blocks = css.split('}');
  const block = blocks.find(
    (b) =>
      b.includes(`[data-theme="${theme}"]`) &&
      b.includes(`[data-mode="${mode}"]`),
  );
  if (!block) throw new Error(`no themes.css block for ${theme}/${mode}`);
  const match = block.match(/--bg:\s*(#[0-9a-fA-F]{3,8})\s*;/);
  if (!match) throw new Error(`no --bg in ${theme}/${mode} block`);
  return match[1].toLowerCase();
}

describe('themeColors', () => {
  it('has an entry for every theme and mode', () => {
    for (const theme of THEMES) {
      for (const mode of MODES) {
        expect(THEME_BG[theme]?.[mode], `${theme}/${mode}`).toMatch(/^#[0-9a-f]{6}$/);
      }
    }
  });

  it('matches the --bg declared in themes.css for all six combinations', () => {
    for (const theme of THEMES) {
      for (const mode of MODES) {
        expect(THEME_BG[theme][mode].toLowerCase(), `${theme}/${mode}`)
          .toBe(bgFromCss(theme, mode));
      }
    }
  });

  it('backgroundFor returns the mapped value', () => {
    expect(backgroundFor('sage', 'dark')).toBe(THEME_BG.sage.dark);
  });
});
```

```ts
import type { Mode, Theme } from './types';

/**
 * Background colour per theme × mode, mirroring the --bg custom property in
 * src/themes.css.
 *
 * This duplicates CSS on purpose. It feeds the <meta name="theme-color">
 * tag, which Chrome reads to tint the title bar of the installed standalone
 * window — and that has to be a real string before paint, not a computed
 * style. themeColors.test.ts parses themes.css and fails if the two drift,
 * so the CSS remains the source of truth.
 */
export const THEME_BG: Record<Theme, Record<Mode, string>> = {
  peach:    { light: '#fef3ec', dark: '#2a1f1c' },
  sage:     { light: '#f4f6ee', dark: '#1f2a1c' },
  lavender: { light: '<from themes.css>', dark: '<from themes.css>' },
};

export function backgroundFor(theme: Theme, mode: Mode): string {
  return THEME_BG[theme][mode];
}
```

Replace both `<from themes.css>` placeholders with the actual lavender values before running.

```ts
function applyToHtml(prefs: Preferences) {
  document.documentElement.setAttribute('data-theme', prefs.theme);
  document.documentElement.setAttribute('data-mode', prefs.mode);

  // Chrome tints the installed standalone window's title bar from this tag.

}
```

### Task 3: Draw the mark

A flat, straight-on stack of three discs — sage on top, two browns below. No perspective, no bevel, no symbols on any face.

**Files:**
- Create: `public/icon.svg`
- Create: `src/components/MesadaMark.tsx`
- Test: `src/components/MesadaMark.test.tsx`

**Interfaces:**
- Produces: `MesadaMark`, a default-exported React component taking `{ size?: number; className?: string; title?: string }`. Task 5 uses it.

**Design constraints (from the spec):**
- Must read unambiguously at 32×32. Geometry is free; the three-disc count and the sage-on-brown relationship are not.
- `public/icon.svg` uses literal hex, because it is served as a static file before React boots and cannot read CSS custom properties.
- `MesadaMark.tsx` uses `var(--positive)` / `var(--text)` / `var(--muted)` so the in-app logo tracks the theme.

- [ ] **Step 1: Write the generator**

Create `scripts/generate-icons.ts`:

```ts
/**
 * Renders public/icon.svg to the PNG sizes Chrome and iOS need.
 *
 * Run manually via `npm run icons`; outputs are committed. This is not part
 * of the build — using Playwright (already a devDependency) keeps an image
 * library out of the dependency tree for a script that runs rarely.
 */
import { chromium } from '@playwright/test';
import { readFileSync, writeFileSync } from 'node:fs';
import { resolve, dirname } from 'node:path';
import { fileURLToPath } from 'node:url';

const root = resolve(dirname(fileURLToPath(import.meta.url)), '..');
const svg = readFileSync(resolve(root, 'public/icon.svg'), 'utf8');

type Target = { file: string; size: number; padding: number };

const TARGETS: Target[] = [
  { file: 'icon-192.png', size: 192, padding: 0 },
  { file: 'icon-512.png', size: 512, padding: 0 },
  { file: 'apple-touch-icon.png', size: 180, padding: 0 },
  { file: 'favicon-32.png', size: 32, padding: 0 },
  // Maskable icons are cropped to a platform-chosen shape. The safe zone is
  // the centre 80%, so the art is inset by 10% on each side to guarantee a
  // circular mask cannot clip the coin stack.
  { file: 'icon-maskable-512.png', size: 512, padding: 0.1 },
];

const browser = await chromium.launch();
try {
  for (const { file, size, padding } of TARGETS) {
    const page = await browser.newPage({
      viewport: { width: size, height: size },
      deviceScaleFactor: 1,
    });
    const inset = Math.round(size * padding);
    await page.setContent(
      `<!doctype html><html><body style="margin:0;background:#fef3ec">
         <div style="width:${size}px;height:${size}px;padding:${inset}px;box-sizing:border-box">
           <div style="width:100%;height:100%">${svg
             .replace(/width="64"/, 'width="100%"')
             .replace(/height="64"/, 'height="100%"')}</div>
         </div>
       </body></html>`,
    );
    const buffer = await page.screenshot({ omitBackground: false });
    writeFileSync(resolve(root, 'public', file), buffer);
    await page.close();
    console.log(`wrote public/${file} (${size}x${size})`);
  }
} finally {
  await browser.close();
}
```

A ratchet. It cannot be a Vitest test: `npm test` runs *before* `npm run build` in both CI and `vercel.json`, so `dist/` does not exist at that point.

**Files:**

- [ ] **Step 1: Write the checker**

Create `scripts/check-bundle-size.ts`:

```ts
/**
 * Post-build gate. Two jobs:
 *
 *   1. Keep the initial JS chunk under budget. Baseline before v2.1 was a
 *      single 493.32 kB chunk (137.59 kB gzipped) with no code splitting.
 *   2. Prove the manifest and every icon it declares actually reached dist/.
 *      This is the only check that inspects Vercel's real build output —
 *      the Vitest suite reads public/, and the E2E suite reads the dev
 *      server.
 *
 * Not a Vitest test: `npm test` runs before `npm run build`, so dist/ does
 * not exist yet at that point.
 *
 * To raise MAX_ENTRY_GZIP_KB, do it deliberately and say why in the commit
 * message. Deleting this check is not the way to make it pass.
 */
import { gzipSync } from 'node:zlib';
import { readFileSync, readdirSync, existsSync } from 'node:fs';
import { resolve, dirname } from 'node:path';
import { fileURLToPath } from 'node:url';

const MAX_ENTRY_GZIP_KB = 0; // ← set in Step 3 from the measured value

const root = resolve(dirname(fileURLToPath(import.meta.url)), '..');
const dist = resolve(root, 'dist');
const assets = resolve(dist, 'assets');

if (!existsSync(dist)) {
  console.error('dist/ not found — run `npm run build` first.');
  process.exit(1);
}

const failures: string[] = [];

// 1. Entry chunk size. Vite names the entry chunk `index-<hash>.js`; lazy
//    chunks are named after their source module.
const entry = readdirSync(assets).find((f) => /^index-.*\.js$/.test(f));
if (!entry) {
  failures.push('no entry chunk matching index-*.js found in dist/assets');
} else {
  const gzipKb = gzipSync(readFileSync(resolve(assets, entry))).byteLength / 1024;
  const rounded = Math.round(gzipKb * 100) / 100;
  console.log(`entry chunk ${entry}: ${rounded} kB gzipped (budget ${MAX_ENTRY_GZIP_KB} kB)`);
  if (gzipKb > MAX_ENTRY_GZIP_KB) {
    failures.push(
      `entry chunk is ${rounded} kB gzipped, over the ${MAX_ENTRY_GZIP_KB} kB budget`,
    );
  }
}

// 2. Manifest and icons present in the built output.
const manifestPath = resolve(dist, 'manifest.webmanifest');
if (!existsSync(manifestPath)) {
  failures.push('dist/manifest.webmanifest is missing — did public/ get copied?');
} else {
  const manifest = JSON.parse(readFileSync(manifestPath, 'utf8'));
  for (const icon of manifest.icons as { src: string }[]) {
    if (!existsSync(resolve(dist, icon.src.replace(/^\//, '')))) {
      failures.push(`manifest declares ${icon.src} but dist/ does not contain it`);
    }
  }
}

if (failures.length > 0) {
  console.error('\nBundle check failed:');
  for (const f of failures) console.error(`  - ${f}`);
  process.exit(1);
}

console.log('Bundle check passed.');
```
