# Per-Expense Currency Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let any individual expense carry its own currency and convert at the rate in force on the day it was paid, with a manual per-expense rate override for when the user transacted off the official rate.

**Architecture:** Two nullable columns on `line_items`. `getBudget` converts **once at the data boundary**: `projected`/`actual` keep their existing meaning (the native stored amounts) and two new fields `baseProjected`/`baseActual` carry the value converted into the user's base currency. Every existing total then changes by one word rather than each component learning about currencies. A `rateResolved` flag marks items whose rate could not be determined so the UI can say so instead of quietly reporting a wrong total.

**Tech Stack:** React 19 + TypeScript 6 + Tailwind 4 + Supabase (Postgres) + Vitest 4 / React Testing Library 16 + Playwright.

**Reference spec:** `docs/superpowers/specs/2026-08-01-accounts-multicurrency-design.md`

## Global Constraints

- **Chunk 2 of 3** of `v1.9`. Chunk 1 (accounts + rates) is shipped and QA-verified. Chunk 3 (receipt attachments) is a separate plan. Do not implement it here.
- **Migration number is `0019`.** `0018` is the last applied migration.
- **A `NULL` currency means "in the user's base currency"** — not USD specifically. Existing rows therefore need no backfill and keep reading correctly.
- **Effective date for conversion is `paid_on` when set, otherwise today.** An unpaid item is an estimate at today's rate because the money has not moved yet.
- **Rate precedence is `rate_units_per_usd` (the per-expense override) before the daily table.**
- **The override is entered in the natural direction** — typing `800` means "800 bolívares to the dollar", which is `units_per_usd`, stored verbatim.
- **Never silently mis-total.** An item whose rate cannot be resolved sets `rateResolved: false`; the UI must surface that rather than let a wrong number pass as correct.
- `npm test` is `vitest run --mode development`. Run it that way.
- Direct push to `staging`. No PRs. QA Supabase ref `ovnkgwnlquislfdwaifh`; PRD `vouazcrsrdnaeivffwot` at release time only.

```ts
// src/utils/itemMoney.ts
import type { Currency } from './currency';
import { rateFor, type RateRow } from './rates';

type ConvertibleItem = {
  currency: Currency | null;
  paidOn: string | null;
  rateUnitsPerUsd: number | null;
};

/**
 * The date whose rate applies. A paid expense converts at the rate in force the
 * day it was paid; an unpaid one is an estimate at today's rate, because the
 * money has not actually moved yet.
 */
export function effectiveDate(paidOn: string | null, today: string): string {
  return paidOn ?? today;
}

/**
 * Units-per-USD for this item, or null if it cannot be resolved.
 *
 * Precedence: the per-expense override wins over the daily table — it exists
 * precisely for when the user transacted at a rate other than the official one.
 * A null currency means the amount is already in the base currency, so 1.
 */
export function itemRate(item: ConvertibleItem, rates: RateRow[], today: string): number | null {
  if (item.rateUnitsPerUsd !== null) return item.rateUnitsPerUsd;
  if (item.currency === null) return 1;
  return rateFor(rates, item.currency, effectiveDate(item.paidOn, today));
}

/** `amount` (in the item's currency) expressed in `base`. Null if unresolvable. */
export function convertAmount(
  amount: number,
  item: ConvertibleItem,
  base: Currency,
  rates: RateRow[],
  today: string,
): number | null {
  const from = itemRate(item, rates, today);
  if (from === null) return null;
  // An untagged item is already in the base currency — no second hop.
  if (item.currency === null) return Math.round(amount * 100) / 100;
  const to = rateFor(rates, base, effectiveDate(item.paidOn, today));
  if (to === null) return null;
  return Math.round((amount * to / from) * 100) / 100;
}
```
