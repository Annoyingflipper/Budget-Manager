# Receipt Attachments Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Attach one or more receipt images or PDFs to any expense, view them without leaving the budget page, and keep them private.

**Architecture:** A `line_item_attachments` table holds pointers; the files live in a **private** Supabase Storage bucket keyed `{user_id}/{line_item_id}/{uuid}.{ext}`, reached through short-lived signed URLs. Images are downscaled in the browser before upload. Because the FK cascade does **not** reach Storage, deletion paths remove objects explicitly, before the rows that name them.

**Tech Stack:** React 19 + TypeScript 6 + Tailwind 4 + Supabase (Postgres + Storage) + Vitest 4 / React Testing Library 16 + Playwright.

**Reference spec:** `docs/superpowers/specs/2026-08-01-receipt-attachments-design.md`

## Global Constraints

- **Chunk 3 of 3** of `v1.9`. Chunks 1 and 2 are shipped and QA-verified.
- **Migration number is `0020`.**
- **The bucket is private.** Receipts show bank details; never make it public, and never persist a signed URL.
- **Storage objects must be deleted before the rows that point at them.** The rows are the only index of what to delete — losing them first strands the files permanently.
- **Allowed types:** `image/*` and `application/pdf`. Max 10 MB per file pre-compression, max 8 attachments per expense.
- **Images downscale to ≤1600px, JPEG q0.8.** If canvas decode fails (HEIC on desktop Chrome), upload the original rather than failing.
- **No `capture` attribute on the file input** — the phone should offer both camera and library.
- `npm test` is `vitest run --mode development`. Direct push to `staging`, no PRs.
- QA ref `ovnkgwnlquislfdwaifh`; PRD `vouazcrsrdnaeivffwot` at release time only.

```sql
create table public.line_item_attachments (
  id            bigint generated always as identity primary key,
  user_id       uuid not null references auth.users on delete cascade,
  line_item_id  bigint not null references public.line_items on delete cascade,
  storage_path  text not null unique,
  mime_type     text not null,
  byte_size     int not null,
  original_name text not null,
  created_at    timestamptz not null default now()
);

create index line_item_attachments_line_item_id_idx
  on public.line_item_attachments (line_item_id);

alter table public.line_item_attachments enable row level security;

create policy "own attachments, mfa required" on public.line_item_attachments
  for all
  using (
    (select auth.uid()) = user_id
    and ((select auth.jwt()) ->> 'aal') = 'aal2'
  )
  with check (
    (select auth.uid()) = user_id
    and ((select auth.jwt()) ->> 'aal') = 'aal2'
  );

-- Private bucket: receipts routinely show bank details and card digits, so they
-- must never be served from a guessable public URL. Access is via signed URLs.
insert into storage.buckets (id, name, public)
values ('receipts', 'receipts', false)
on conflict (id) do nothing;

-- Paths are {user_id}/{line_item_id}/{uuid}.{ext}, so the first path segment is
-- the owner and the same AAL2 rule as every other table applies.
create policy "own receipt objects, mfa required" on storage.objects
  for all
  using (
    bucket_id = 'receipts'
    and (storage.foldername(name))[1] = (select auth.uid())::text
    and ((select auth.jwt()) ->> 'aal') = 'aal2'
  )
  with check (
    bucket_id = 'receipts'
    and (storage.foldername(name))[1] = (select auth.uid())::text
    and ((select auth.jwt()) ->> 'aal') = 'aal2'
  );
```

```ts
const DEFAULT_MAX_EDGE = 1600;
const QUALITY = 0.8;

/**
 * Downscale + re-encode an image before upload. Supabase's free tier is 1 GB;
 * raw phone photos run 3–5 MB (~240 receipts) while compressed ones land near
 * 200 KB. Receipts stay legible at 1600px.
 *
 * Every failure path returns the ORIGINAL file: losing compression is a far
 * better outcome than losing the receipt. HEIC in particular decodes on Safari
 * but not on desktop Chrome.
 */
export async function compressImage(file: File, maxEdge = DEFAULT_MAX_EDGE): Promise<File> {
  if (!file.type.startsWith('image/')) return file;

  let bitmap: ImageBitmap;
  try {
    bitmap = await createImageBitmap(file);
  } catch {
    return file;
  }

  const longest = Math.max(bitmap.width, bitmap.height);
  if (longest <= maxEdge) {
    bitmap.close?.();
    return file;
  }

  const scale = maxEdge / longest;
  const width = Math.round(bitmap.width * scale);
  const height = Math.round(bitmap.height * scale);

  const canvas = document.createElement('canvas');
  canvas.width = width;
  canvas.height = height;
  const ctx = canvas.getContext('2d');
  if (!ctx) { bitmap.close?.(); return file; }
  ctx.drawImage(bitmap, 0, 0, width, height);
  bitmap.close?.();

  const blob = await new Promise<Blob | null>((resolve) =>
    canvas.toBlob(resolve, 'image/jpeg', QUALITY),
  );
  if (!blob) return file;

  const name = file.name.replace(/\.[^.]+$/, '') + '.jpg';
  return new File([blob], name, { type: 'image/jpeg' });
}
```

- [ ] **Step 2–4:** implement, run, commit. Key shapes:

```ts
const BUCKET = 'receipts';
export const MAX_BYTES = 10 * 1024 * 1024;
export const MAX_PER_ITEM = 8;
const ALLOWED = (t: string) => t.startsWith('image/') || t === 'application/pdf';

export async function removeAttachmentsForItems(lineItemIds: number[]): Promise<void> {
  if (lineItemIds.length === 0) return;
  // 1. read the manifest FIRST — these rows are the only record of what to delete
  const { data: rows, error } = await supabase
    .from('line_item_attachments').select('storage_path').in('line_item_id', lineItemIds);
  if (error) throw error;
  if (!rows?.length) return;
  // 2. remove objects; throw on failure so the manifest survives for a retry
  const { error: storageErr } = await supabase.storage.from(BUCKET)
    .remove(rows.map((r) => r.storage_path as string));
  if (storageErr) throw storageErr;
  // 3. only now drop the rows
  const { error: rowErr } = await supabase
    .from('line_item_attachments').delete().in('line_item_id', lineItemIds);
  if (rowErr) throw rowErr;
}
```

Upload orders itself the other way (object first, then row) and cleans up the object if the insert fails, so the only possible inconsistency is a stray object — which is detectable — never a row pointing at a missing file.
